# DailyBeat hardening implementation

Based on main `cb30dbc` (v4.1.3), including the latest Days-card and palette changes. This is a QA change, not a production release.

| Finding | Change | Evidence required |
|---|---|---|
| Overlapping private zones / failed privacy reads | Match all private zones; a failed places query aborts enrichment and retains capture for retry; check privacy again at HTTP send | Overlap regression, network gate tests |
| Stay discarded on battery sleep | Require an observed eight-minute stay before sleep; keep checkpoint; record a suspension boundary so sleep never becomes transit | Sleep/restart regression and physical trial |
| GPS labels in cloud prompts | Plain unnamed-place fallback; remove legacy numeric location labels at outbound boundary | Day context regression |
| Sleep/resume without supported permissions | Sleep requires a working motion watcher plus background location; FOSS stays active; blocked background resume provides a tap-to-resume notification | Permission/backend policy tests and both APK variants |
| Refresh token bypass of deletion step-up | Verified identity plus recent password AMR, not token iat | Deno HTTP handler tests |
| Backup size / replacement risk | Streaming database pages, gzip then AES-GCM, authenticated page manifests, immutable versions, newest five complete versions, transactional paged restore | 80k points, wrong key, page substitution, failed upload, pgTAP, Auth/HTTP smoke |
| Capture write durability | Room inbox; derived visit, event, breadcrumb, checkpoint and acknowledgement in one transaction; WorkManager retries storage failures | SQLite trigger fault, process replacement, duplicate sample tests |
| Shared public geocoder endpoint | Default offline; optional runtime managed HTTPS endpoint; public Nominatim automatic use rejected | Settings/input and geocoder tests |
| 200% text clipping | Stack Today metrics; allow navigation labels to wrap | Device screenshots and accessibility assertions |
| Old-history access and query count | Thirty-day windows with date selection; six range queries per page | Range-loader tests and UI trial |
| Support and operations | Explicit content-free diagnostic preview; repeatable guarded launch benchmark; recovery/runbook | Output and policy checks |

The new backend migration must be deployed before an archive-capable production APK. Legacy
v1 encrypted and readable snapshots stay untouched and remain available through their existing
restore paths. Archive recovery is authenticated before local records are touched; all table
inserts commit together, and a failed restore rolls back. Recovery passphrases remain separate
from sign-in passwords, are never uploaded, and cannot be reset.

The archive uses PBKDF2-HMAC-SHA256 (600,000 iterations, random 128-bit salt), AES-256-GCM
(random 96-bit nonce per page), and version ID + page index + format parameters as authenticated
data. Every page is gzip-compressed before encryption. An encrypted manifest binds page hashes
and creation time. Limits: 4 MiB expanded per page, 1 MiB encrypted per page, 2,048 pages and
64 MiB per archive. These are bounded safety limits, not a promise of unlimited storage.
An upload becomes visible only after the database verifies the complete page sequence. Previous
completed versions are pruned only after a new version commits. An uncertain publish response
cannot cause cleanup to delete a committed archive.

Android compatibility is a separate focused commit in this branch. The source policy for the
minimum supported Android 16 toolchain is [AGP 8.10](https://developer.android.com/build/releases/agp-8-10-0-release-notes).
Background starts follow [Android foreground service restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start).
Destructive step-up uses [Supabase authentication-method timestamps](https://supabase.com/docs/guides/auth/jwt-fields).
The default lookup policy avoids relying on the [public Nominatim service](https://operations.osmfoundation.org/policies/nominatim/).

Real-device battery usage, OEM background survival, external geocoder SLA, and 14-day stop recall
require a controlled field trial. A passing emulator suite does not establish these properties.
